# Resend parity — wave 8A

The [Opensend contract](../openapi/opensend.yaml) serves **81 operations**: **79** overlap the supplied Resend snapshot and **2** are SMTP bridge extensions. Of the snapshot’s **113 operations**, **71 are served**, **8 partial**, and **34 missing**. This wave 8A audit includes the existing REST surface and its nine added compatibility operations; other wave 8 lanes own the remaining missing operations.

`served` means an operation exists with no identified resource-specific wire gap after the common differences below; `partial` means it exists with a documented field, status, validation or behavior gap; `missing` means no matching REST registration, even if the dashboard has a Convex function. Parameter placeholder spelling does not affect matching (`{email_id}` and `{id}` are the same URL pattern). The table uses upstream spellings; the contract uses actual handler spellings. This classification does not treat upstream missing `required` arrays as evidence that live Resend omits fields. Served rows can still share the documented self-hosted deviations below; this classification does not claim live provider equivalence.

## Common differences and table shorthand

These apply to served/partial rows, even when not repeated. All REST routes, including OAuth grants, now use apiRoute:

- **G — identity/auth/errors/transport:** opaque Convex ids rather than UUIDs, installation-specific Convex site origin, `os_` bearer keys and OAuth tokens. Team full access required except email sends; SMTP excludes OAuth. Standard error envelope `{statusCode,name,message}`; missing key 401 `missing_api_key`, restricted key 401 `restricted_api_key`, invalid key 403 `invalid_api_key`, OAuth scope 403 `invalid_permission`, missing/foreign resource 404 `not_found`. Invalid/missing input generally 422 `validation_error`/`missing_required_field`; sending attachments can use `invalid_attachment`. JSON parse 400 `validation_error`; oversized body 413 `validation_error`; idempotency key 400 `invalid_idempotency_key`; conflicts 409 `invalid_idempotent_request`/`concurrent_idempotent_requests`; throttling 429 `rate_limit_exceeded`; unexpected failures 500 `application_error`. Plain Convex validation exceptions collapse to `validation_error`, so precise Resend error messages/names are not guaranteed for all failure branches. HTTP 200 is the default success; differing create statuses appear per row. No CORS. Unknown fields/query parameters are ignored except explicitly rejected fields. Optional string/boolean parser fields commonly accept null as omission; required fields reject null.
- **P — pagination:** every list accepts limit 1–100 (default 20) and mutually exclusive after/before resource ids, emits `{object:"list",has_more,data}`, newest-first. Unlike Resend endpoints that document all rows when limit is absent, Opensend always bounds the page. Invalid/foreign anchor is 422. Cursors now use the full index key, including creation time and id tie-breaks; received mail also includes receivedAt. Equal-timestamp records are not skipped. Relation ordering is specified per row. Snapshot shared pagination parameters do not document a default; do not infer exact live parity from them.
- **G — rate/idempotency/retention:** 10 requests/s per team shared by keys; `ratelimit-limit`, `ratelimit-remaining`, `ratelimit-reset` (seconds until window reset, not epoch), 429 `retry-after`. Pre-accounting auth/body-size refusals may omit rate headers. Any POST can use Idempotency-Key (1–256 chars) with 24-hour replay, hashing exact method/path/body bytes, server error releases key. Default JSON limit 1 MiB. Logs are kept 30 days and pre-auth failures cannot be logged to a team. No automatic provider resend after ambiguous SES timeout. This is broader POST replay support than email-only SDK options imply.
- **D — domains:** same four selectable AWS regions; installation region default. Async provisioning/deletion, narrower domain statuses pending/verified/partially_verified/failed (no not_started/partially_failed). DNS status pending/verified/temporary_failure; includes DMARC, no TrackingCAA or CAA type. Existing MX return-path records map to SPF. Tracking starts after CNAME verification and redirects over HTTP; HTTPS requires separate operator CDN/certificate. Receiving depends on SES regional support.
- **C — contacts:** shared dashboard normalization and limits: 100 properties, 500 segments, 100 topics/team; names/property values up to 1000 characters; normalized email up to 254. Only string/number properties; JSON numbers stay numeric on retrieval. REST property keys preserve spelling, permit alphanumerics/underscore (1–50), and reserve email/first_name/last_name/unsubscribed. The dashboard keeps its existing normalization. A whole properties:null is rejected; individual null values clear. Empty string/null values clear to fallback; getter includes defined properties with typed value/default/null. CSV dashboard imports suppress contact webhooks at this base (`csvImport`), superseding the old follow-up note.
- **T — templates:** only string/number variables, max 50, unique identifier keys max 50; reserved names FIRST_NAME/LAST_NAME/EMAIL/RESEND_UNSUBSCRIBE_URL/contact/this rejected in explicit definitions. String defaults max 2000; HTML/text each 256 KiB, names 256, aliases 128, subject 998, sender 512; reply-to max 50 valid addresses. One mutable draft plus one published snapshot, no version-history model; inline variables inferred with HTML escaping. `current_version_id` identifies the current draft revision; variables keep independent ids and timestamps across edits. Legacy templates without metadata use their template timestamps until edited. Missing alias generated/unique by dashboard rules. Raw `react` is SDK work. The supplied snapshot lists boolean/object/list variables, but the current [create-template docs](https://resend.com/docs/api-reference/templates/create-template.md) still document only string/number: wider-type parity needs an upstream decision, not an assumption about the live API.
- **B — broadcasts:** body HTML/text max 256 KiB each; subject max 998, name/preview/from/first reply-to max 1000, up to 50 valid reply-to addresses. Draft/canceled editable; other states name-only. `queued` means fan-out/in-flight, `sent` means eligible copies settled, `failed` includes fan-out or send failure. Resolves recipients in bounded pages with creation cutoff; preferences/suppression checked at fan-out and pre-delivery, signed unsubscribe links per recipient. No new UI controls. Cancellation only before resolution begins; deletion cancels a scheduled send.
- **E — events:** reserved prefix opensend: rather than resend:, trimmed event names max 256, schema keys trimmed and blanks discarded, remaining max 50 keys using letters/numbers/underscore; types string/number/boolean/date. Payload max 64 KiB, depth 32, printable ASCII keys excluding leading $. All required declared properties validated without coercion. Id or name lookup, no user event id (use idempotency); sent events retained 30 days, custom events not forwarded to webhooks.
- **R — receiving:** raw MIME limit 40 MiB, 100 attachments, 100 addresses/field, 512 headers, 32 KiB attachment metadata and envelope metadata each, 600 KiB combined decoded HTML/text/headers; parse failures retain raw MIME and empty decoded data. 30-day retention, one-hour local signed downloads. Inline-image fallback uses >6 MiB/file or >8 MiB projected HTML; these smaller limits fit Convex response limits.
