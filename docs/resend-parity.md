# Resend parity at Opensend `0b10d8d`

The [Opensend contract](../openapi/opensend.yaml) serves **72 operations**: **70** overlap the supplied Resend snapshot and **2** are SMTP bridge extensions. Of the snapshot’s **113 operations**, **24 are served**, **46 partial**, and **43 missing**. This is a contract audit of the base commit, not a claim about lane 7A’s concurrent changes.

`served` means an operation exists with no identified resource-specific wire gap after the common differences below; `partial` means it exists with a documented field, status, validation or behavior gap; `missing` means no matching REST registration, even if the dashboard has a Convex function. Parameter placeholder spelling does not affect matching (`{email_id}` and `{id}` are the same URL pattern). The table uses upstream spellings; the contract uses actual handler spellings. This classification does not treat upstream missing `required` arrays as evidence that live Resend omits fields. The 24 served rows can still share documented common deviations such as bounded default pagination; this count is not 24 fully identical endpoints.

## Common differences and table shorthand

These apply to every apiRoute-based served/partial row, even when not repeated. The two legacy OAuth grant operations bypass this wrapper; their rows document the exceptions:

- **G — identity/auth/errors/transport:** opaque Convex ids rather than UUIDs, installation-specific Convex site origin, `os_` bearer keys and OAuth tokens. Team full access required except email sends; SMTP excludes OAuth. Standard error envelope `{statusCode,name,message}`; missing key 401 `missing_api_key`, restricted key 401 `restricted_api_key`, invalid key 403 `invalid_api_key`, OAuth scope 403 `invalid_permission`, missing/foreign resource 404 `not_found`. Invalid/missing input generally 422 `validation_error`/`missing_required_field`; sending attachments can use `invalid_attachment`. JSON parse 400 `validation_error`; oversized body 413 `validation_error`; idempotency key 400 `invalid_idempotency_key`; conflicts 409 `invalid_idempotent_request`/`concurrent_idempotent_requests`; throttling 429 `rate_limit_exceeded`; unexpected failures 500 `application_error`. Plain Convex validation exceptions collapse to `validation_error`, so precise Resend error messages/names are not guaranteed for all failure branches. HTTP 200 is the default success; differing create statuses appear per row. No CORS. Unknown fields/query parameters are ignored except explicitly rejected fields. Optional string/boolean parser fields commonly accept null as omission; required fields reject null.
- **P — pagination:** every list accepts limit 1–100 (default 20) and mutually exclusive after/before resource ids, emits `{object:"list",has_more,data}`, newest-first. Unlike Resend endpoints that document all rows when limit is absent, Opensend always bounds the page. Invalid/foreign anchor is 422. Cursors bound by creation timestamp only (receivedAt for received mail), with no id tiebreaker: equal-timestamp rows at a page boundary can be skipped. Relation ordering is specified per row. Snapshot shared pagination parameters do not document a default; do not infer exact live parity from them.
- **G — rate/idempotency/retention:** 10 requests/s per team shared by keys; `ratelimit-limit`, `ratelimit-remaining`, `ratelimit-reset` (seconds until window reset, not epoch), 429 `retry-after`. Pre-accounting auth/body-size refusals may omit rate headers. Any POST can use Idempotency-Key (1–256 chars) with 24-hour replay, hashing exact method/path/body bytes, server error releases key. Default JSON limit 1 MiB. Logs are kept 30 days and pre-auth failures cannot be logged to a team. No automatic provider resend after ambiguous SES timeout. This is broader POST replay support than email-only SDK options imply.
- **D — domains:** same four selectable AWS regions; installation region default. Async provisioning/deletion, narrower domain statuses pending/verified/partially_verified/failed (no not_started/partially_failed). DNS status pending/verified/temporary_failure; includes DMARC, no TrackingCAA or CAA type. Existing MX return-path records map to SPF. Tracking starts after CNAME verification and redirects over HTTP; HTTPS requires separate operator CDN/certificate. Receiving depends on SES regional support.
- **C — contacts:** shared dashboard normalization and limits: 100 properties, 500 segments, 100 topics/team; names/property values up to 1000 characters; normalized email up to 254. Only string/number properties; JSON numbers stay numeric on retrieval. Property keys must start with a letter, are lowercased, and reserve email/first_name/last_name/unsubscribed. A whole properties:null is rejected; individual null values clear. Empty string/null values clear to fallback; getter includes defined properties with typed value/default/null. CSV dashboard imports suppress contact webhooks at this base (`csvImport`), superseding the old follow-up note.
- **T — templates:** only string/number variables, max 50, unique identifier keys max 50; reserved names FIRST_NAME/LAST_NAME/EMAIL/RESEND_UNSUBSCRIBE_URL/contact/this rejected in explicit definitions. String defaults max 2000; HTML/text each 256 KiB, names 256, aliases 128, subject 998, sender 512; reply-to max 50 valid addresses. One mutable draft plus one published snapshot, no version-history model; inline variables inferred with HTML escaping. `current_version_id` is stable draft id, variable responses omit ids/timestamps. Missing alias generated/unique by dashboard rules. Raw `react` is SDK work. The supplied snapshot lists boolean/object/list variables, but the current [create-template docs](https://resend.com/docs/api-reference/templates/create-template.md) still document only string/number: wider-type parity needs an upstream decision, not an assumption about the live API.
- **B — broadcasts:** body HTML/text max 256 KiB each; subject max 998, name/preview/from/first reply-to max 1000, up to 50 valid reply-to addresses. Draft/canceled editable; other states name-only. `queued` means fan-out/in-flight, `sent` means eligible copies settled, `failed` includes fan-out or send failure. Resolves recipients in bounded pages with creation cutoff; preferences/suppression checked at fan-out and pre-delivery, signed unsubscribe links per recipient. No new UI controls. Cancellation only before resolution begins; deletion cancels a scheduled send.
- **E — events:** reserved prefix opensend: rather than resend:, trimmed event names max 256, schema keys trimmed and blanks discarded, remaining max 50 keys using letters/numbers/underscore; types string/number/boolean/date. Payload max 64 KiB, depth 32, printable ASCII keys excluding leading $. All required declared properties validated without coercion. Id or name lookup, no user event id (use idempotency); sent events retained 30 days, custom events not forwarded to webhooks.
- **R — receiving:** raw MIME limit 40 MiB, 100 attachments, 100 addresses/field, 512 headers, 32 KiB attachment metadata and envelope metadata each, 600 KiB combined decoded HTML/text/headers; parse failures retain raw MIME and empty decoded data. 30-day retention, one-hour local signed downloads. Inline-image fallback uses >6 MiB/file or >8 MiB projected HTML; the existing REST prose still says 100 MiB and should be corrected by its owning lane.

## Recommended implementation order

First reconcile the new spec with lane 7A changes and rerun the registration/response contract tests. Fix inexpensive existing-route gaps before adding features: create 201 statuses, documented nullability/response projections, contact email semantics (docs describe email lookup, while the snapshot implies an update field), topic_id send behavior and strict/permissive batch handling. Treat snapshot errors (email cancel/update schema) as documentation corrections, not a reason to return the wrong payload. Decide whether opaque ids, self-hosted limits and SES restrictions remain intentional differences.

For missing resources, work from small adapters toward new backend features:

1. **API-key update and deprecated audience aliases** (1 + 4 snapshot operations): existing apiKeys.update and segment helpers; add REST authorization and projection. Include older audience contact overload routes separately if SDK compatibility requires them; they are absent from the snapshot inventory.
2. **Repair the two partial OAuth grants routes before new resources:** `/oauth/grants` list/revoke already exist in `convex/oauthHttp.ts`; unify bearer authorization, Resend response/error projection and bounded cursor pagination. The underlying grant storage/revocation is already implemented; these are not missing endpoints.
3. **Suppressions** (6): existing `convex/suppressions.ts` owns storage, add/remove, SES tenant cleanup. Extract reusable authorized helpers, translate reasons, add id/email retrieval and atomic bounded batch operations; no new SES sending feature.
4. **Webhooks** (10): `convex/webhooks.ts` already has CRUD, signing secret, rotation, deliveries, attempts and replay. REST is mostly adapters; audit rotation overlap and event/attempt projections against Resend before claiming identical behavior.
5. **Outbound attachments and broadcast reporting** (2 + 2): outbound file storage and broadcast recipient history already exist. Add stable outbound attachment ids and downloads; recipient REST uses existing history. Clicked-link aggregation needs extra work to deduplicate URL clicks across recipient messages. Broadcast send/cancel/duplicate and template publish/duplicate are already served at this base; do not rebuild them.
6. **Automations** (9): graph/run/step storage and workflow runtime exist in `convex/automations.ts` and `automationRuntime.ts`. Requires graph/status/stop translation and credential-safe helpers, not a new workflow engine. Validate draft/published/stop semantics and run pagination before exposing the full surface.
7. **Contact imports** (3): contact upsert/CSV batches exist, but an import is not yet a persistent job resource. Build job storage, bounded execution, durable counts/errors and multipart/CSV or safely fetched source transport. Preserve current csvImport webhook suppression. This is more than a thin REST wrapper.
8. **Metrics and usage** (1 + 1): metrics aggregates and SES quotas exist. Build requested dimension/granularity/timezone queries; choose honest self-hosted usage semantics rather than inventing a Resend billing plan.
9. **Email share and domain claims** (1 + 3): new public expiring-share capabilities and cross-team DNS claim/ownership-transfer lifecycle. These require new backend/security behavior; keep last.

The 43 missing snapshot operations are accounted for above. No IAM policy change is proposed by this contract lane. Reassess permissions when implementing features that actually call AWS. The spec has no dependency on the private marketing repository, and no dashboard design or interaction changed.
