# IVR API and runtime (8d-3)

IVRs are team resources. Use `ivrs:read` to list/read/dry-run validation and
`ivrs:write` to create/update/delete. `POST /ivrs`, `GET /ivrs`,
`GET|PATCH|DELETE /ivrs/{id}` and `POST /ivrs/{id}/validate` are exposed through
`opensend.ivrs.create/list/get/update/remove/validate` and the equivalent MCP tools.
Lists use `limit`, `after`, `before`. Create supports `Idempotency-Key`; menus in a
PATCH replace the complete array. Validation merges a patch with the saved
configuration and returns `{valid, errors}` without writes. Definitions use camelCase;
resource metadata uses `created_at`, `updated_at`, `prompt_status`.

The shared pure parser is `lib/ivr.ts` (`parseIvr`, `validateIvr`, `isIvrOpen`). It
checks unique/reachable menu IDs, DTMF keys, dangling submenus, automatic cycles,
50 menus, 12 options per menu, 2,000 characters per TTS prompt, and a 240 KB total
definition bound. Input-driven menu loops are allowed; no-input/failure loops are
rejected. Menu defaults are timeout 5 seconds, two retries after the first attempt,
and one digit; configurable bounds are 1–30 seconds, 0–5 retries, 1–12 digits.
Options are keyed by single `0–9`, `*`, `#`; multiple collected digits are invalid
unless the definition format gains sequence keys in a later version. Keyword/speech
recognition is out of scope and requires 8d-2 streaming STT.

```json
{
  "name": "Reception",
  "language": "en",
  "entryMenuId": "main",
  "menus": [
    {
      "id": "main",
      "name": "Main",
      "prompt": { "kind": "audio", "fileId": "FINALIZED_TEAM_FILE_ID" },
      "options": { "1": { "kind": "voicemail" } },
      "noInputAction": { "kind": "hangup" },
      "failureAction": { "kind": "hangup" }
    }
  ]
}
```

Upload WAV, MP3 or OGG through the existing `/media/uploads` flow with `use: "ivr"`
(`media:write`); finalize using `storage_id`, then reference the returned file id.
Type, size (1 byte–16 MiB), ready state and team ownership are rechecked. No new
storage provider or public file bucket is involved. Playback uses the image’s libsndfile (MP3 support since 1.1.0; Ogg Opus since
1.0.29), as documented in the [supported formats](https://libsndfile.github.io/libsndfile/formats.html)
and [FAQ](https://libsndfile.github.io/libsndfile/FAQ.html). The API validates
the container MIME type and metadata; damaged or mislabeled audio can still fail playback.

The [Playground and TTS layer](voice-playground.md) renders typed prompts through
team ElevenLabs/Sarvam keys. Set `promptVoice: {provider, voice, language, credentialId}`;
reads expose `prompt_renders` and `prompt_status`, including safe per-prompt failures.
`POST /ivrs/{id}/render` (ivrs:write), SDK `ivrs.render` and MCP `render-ivr` retry
failed/expired renders and reuse ready audio. WAV output is PCM16 mono at 16 kHz,
served through the existing signed HTTP-cache path. Rendering is bounded and leased,
with team-scoped content hashes. PATCH null clears promptVoice or businessHours.
Legacy text without a provider remains pending. Missing prompts still take the
configured failure action and ultimately hang up if no fallback can play.

POST `/whatsapp/phone-numbers/{id}/calling` with
`{"routing":{"kind":"ivr","ivrId":"IVR_ID"}}` enables gateway handling.
`routing` also supports `{kind:"agents"}` and `{kind:"api"}`; the latter selects
API handling. Settings resolve IVR ownership before Graph requests. Reads expose
routing. Configured inbound IVRs automatically pre-accept/accept through Graph,
then route only after Graph success. An explicit claimed agent still takes precedence
in the integrator accept path. Legacy calls without configured routing retain the
foundation demo. Outbound behavior stays as in the calling core.

`businessHours` reuses the calling `call_hours` shape: `status`, `timezone_id`,
`weekly_operating_hours` (two HHmm ranges per weekday), `holiday_schedule` and a
required `closedAction`. Hours are evaluated in Convex when the IVR starts, with
IANA timezone/DST handling and exclusive close times. A matching holiday overrides
the weekly schedule; `0000`–`0000` closes that date. Sessions snapshot definitions,
so edits/deletion do not change an active menu tree.

Gateway endpoints are signed with the existing HMAC/raw-body/nonce envelope:

- `POST /calling/gateway/ivr/start` with `{callId, ivrId}` returns an entry decision.
- `POST /calling/gateway/ivr/next` with `{callId, ivrId, menuId, digits, step?}` uses
  digits or `timeout`/`invalid`. The gateway supplies the monotonically increasing
  `step`, preventing stale/concurrent requests. No transport retries are issued.

Every decision is authorized against persisted call/team/session state. Prompt URLs
bind call id, file id and a ten-minute expiry to a dedicated HMAC purpose. The audio
handler verifies the signature and active call/file ownership, streams Convex storage,
and supports `http_cache://`. Only URLs generated by the backend reach ESL. The
runner uses `http_prefetch` for entry/invalid prompts, clears both digit variables,
uses async/full `play_and_get_digits` and `none` as terminator so `#` is selectable.
The existing FreeSWITCH duration cap and remote hangup cancel control requests.
Agent actions reserve an available, authorized browser agent and transfer to
`agent-route`; absence takes the menu failure action. Voicemail uses 8d-1's recorder.
Bot actions pass `target: "bot"`, botId and the persisted team to the voice runtime;
bot admission and authorization use the shared voice runtime.

Webhook actions POST `{call, ivrId, menuId, digits}` to a public HTTPS endpoint through
`publicFetch` (DNS-pinned, no redirects, 3-second timeout, 8 KB response limit).
Standard Webhooks/Svix headers sign the exact body. `secretId` selects an existing
same-team webhook secret; otherwise use `webhook_signing_secret` returned on the IVR.
Playground decision requests include `call.test: true`. The response is exactly `{action: ACTION}` using the fixed action schema. Nested
webhook actions, arbitrary commands and dangling submenus are refused. Failure
falls back to the menu's `failureAction`; a webhook fallback cannot call another
webhook. Decisions are durably claimed before external IO and completed afterward;
a lost response is not blindly retried. Remote hangup finishes a pending decision.

Call reads expose `ivr_id`, bounded `ivr_path` (100 entries), `ivr_outcome`.
Each path entry is `{menuId, digits, action, at}`. Business-hours paths use
`menuId: "business_hours", digits: "closed"`; interrupted IVRs use `digits: "hangup"`.
Terminal selection/handoff emits `whatsapp.call.ivr_completed` exactly once, with
`{id, account_id, ivr_id, path, final_action}`. The OpenAPI webhook section includes
a complete two-menu sample payload. It describes IVR completion/handoff, not whole-call
completion; the normal call lifecycle event follows when the call ends.

8d-4 can call the REST API or `ivr.definitions.dashboardList/dashboardGet/dashboardWrite`
with the existing authenticated team context, import `lib/ivr.ts` for form validation,
and read `ivr_path`/`ivr_outcome` from the existing call endpoints. Supply editor menu
arrays as whole replacements, display pending_render and use the existing upload
components. Playground now supplies the editors and browser testers described in voice-playground.md.

Schema changes are new `ivrs`, `ivrPromptRenders`, `ivrSessions`, optional fields on
calls/settings, and a routing-reference index. Team cleanup includes all new tables.
Hand-registered Convex API types need normal codegen during integration, without
running a backend from this lane. The integrated union is `agents | api | bot | ivr`, derived from the shared routing definition. Bot and IVR references use typed Convex IDs; both routing indexes are retained.

The runtime syntax was checked against the official
[application reference](https://developer.signalwire.com/freeswitch/dialplan/dptools/),
[tagged PAGD source](https://github.com/signalwire/freeswitch/blob/v1.11.3/src/mod/applications/mod_dptools/mod_dptools.c),
[tagged HTTP cache source](https://github.com/signalwire/freeswitch/blob/v1.11.3/src/mod/applications/mod_http_cache/mod_http_cache.c)
and [async event-socket manual](https://developer.signalwire.com/freeswitch/integration/event-socket/).

For the isolated harness, take the lock from the brief, rebuild its images, start
its media services, and run meta-peer with `ivr-engine`. The fake backend serves
signed WAV prompts and records main digit 1 → support digit 2 → voicemail, through
real Meta/Janus RFC2833 and outbound ESL. Convex tests separately prove durable path
recording, team isolation, all actions, hours, webhook signing/fallback, nonce/state
checks and signed audio serving. The dashboard/API Playwright flow is wired into
`tests/e2e/auth.spec.ts` for the lead's integration run; do not run its Docker project
from this lane.

## Prompt audio quality

New WAV, MP3 and OGG uploads are decoded once, during upload completion, by the
calling gateway's authenticated `/prompts/normalize` endpoint. Its ffmpeg process
accepts only local pipe data, has bounded concurrency, a 20-second timeout and a
16 MiB output limit. Stored prompts are mono, signed 16-bit PCM WAV at 48 kHz.
The limit also bounds decoded duration to approximately 174 seconds. Conversion
must succeed before a file becomes ready; an idempotent completion does not convert
it again. The calling gateway must be configured and available when uploading.

ElevenLabs renders request `pcm_44100` (requires the provider's Pro tier or above);
Sarvam Bulbul v3 requests 24 kHz PCM WAV. Both then use the same 48 kHz converter.
Renderer version keys changed so new renders do not reuse old 16 kHz assets.
Re-save/re-render existing TTS prompts and re-upload existing recorded prompts to
replace their old stored audio. Upsampling cannot restore detail missing from a
low-quality source.

Playback still uses call-scoped signed URLs and `http_cache://` with `mod_sndfile`.
FreeSWITCH's Meta leg is Opus at 48 kHz / 20 ms. The local ceiling is 64 kbps;
`bitrate-negotiation` and `asymmetric-sample-rates` respect lower remote fmtp limits.
The Docker `ivr-engine` case verifies a 10 kHz tone at the fake Meta receiver,
which would disappear through an 8 or 16 kHz PCM bottleneck.

Provider references: [ElevenLabs formats](https://elevenlabs.io/docs/api-reference/text-to-speech/convert),
[Sarvam sample rates](https://docs.sarvam.ai/api-reference/text-to-speech/convert),
[pinned FreeSWITCH Opus negotiation](https://github.com/signalwire/freeswitch/blob/v1.11.3/src/mod/codecs/mod_opus/mod_opus.c).
