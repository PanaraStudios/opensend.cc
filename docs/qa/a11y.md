## Automated coverage

`tests/e2e/screens-tour-flow.ts` runs `@axe-core/playwright` on every visited tour
scene after its existing readiness checks and screenshot. It uses the tags
`wcag2a`, `wcag2aa`, `wcag21a`, and `wcag21aa` for WCAG 2.1 A/AA, plus
`best-practice` for additional heading, landmark, and structural checks. See
[Playwright's accessibility guide](https://playwright.dev/docs/accessibility-testing)
and [axe's rule list](https://dequeuniversity.com/rules/axe/html/4.13).

The existing scene matrix is retained: light/dark at 1280 and 390 px, including
the dialogs and pickers the tour opens. Existing mobile editor skips remain;
only visited scenes are scanned. The tour timeout is now 30 minutes to allow
for the additional per-scene analysis.

Each violating node produces an `a11y` finding in
`$OPENSEND_TEST_RESULTS/tour/findings.json`, with the scene name, theme, width,
screenshot filename, and `detail` containing:

- `ruleId` and `impact` from axe;
- `target`, a selector including frame/shadow ancestry, capped at 240 characters;
- `summary`, axe's failure explanation, without copying the node's HTML;
- `allowlisted`, whether the rule is explicitly exempted from failure gating.

Every impact is recorded. Non-allowlisted `serious` and `critical` violations
fail the tour's final assertion. `minor`, `moderate`, and unknown impacts remain
diagnostic findings. An axe execution error is recorded as `a11y-scan-error` and
fails the tour; readiness failures still receive an attempted scan. Findings
continue to be saved after each scene. Existing overflow, runtime, error-page,
and screen failures still fail; raw-code findings still only report.

## Allowlist

The explicit, commented rule allowlist is `A11Y_RULE_ALLOWLIST` in
`tests/e2e/a11y-policy.ts`. It is **empty**: no third-party or deliberate
exception has been established from browser evidence yet. No rules or page
regions are excluded from scanning.

If the Linux findings establish an unavoidable exception, add its exact rule
id with a comment naming the affected component, why it is third-party or
deliberate, and the expected resolution. Document that reason here too. Keep
the list short. Exceptions continue to appear in the JSON; they only bypass
the severity gate. Do not exempt general label or contrast rules to hide our
own component failures.

## Changes

- `174813d` — adds the devDependency, per-scene axe findings, failure gating,
  and unit tests for severity and explicit rule exceptions.
- `b5ecb81` — connects shared `Field`/`FieldLabel` to Base UI so fields without
  explicit `htmlFor` can name inputs, selects, comboboxes, checkboxes, and
  switches. Standalone labels and labels wrapping fields retain their native
  behavior. Textareas now participate in the same Field association.
  Combobox toggle, clear, and chip-remove buttons have accessible names.
  ListToolbar search fields, topic-subscription switches, bulk topic/segment
  checkboxes, and broadcast progress receive specific names.
  Command-dialog title/description move inside the dialog. ItemGroup stops
  claiming a list without listitem children. Empty titles default to `h2` to
  follow the page heading; editor chrome supplies an `h1`. The desktop sidebar
  exposes a named navigation landmark.
  Light/dark faint text, light status colors, destructive-button gradients,
  field borders, and unchecked switch tracks gain contrast. Date-range days
  outside the active month retain readable contrast. The existing semantic
  empty-heading test now expects `h2`.
- `66a62b6` — keeps explicit input, textarea, and select names distinct inside
  fields containing several controls, while retaining automatic names for
  controls that rely on the visible FieldLabel.

The source review found no clear nested-button case to restructure. The axe
pass will assess the rendered composition of triggers, links, and controls.
