## Automated coverage

`tests/e2e/screens-tour-flow.ts` keeps the visual scene matrix: light/dark at
1280 and 390 px, including the same visited dialogs and pickers. Readiness,
screenshots, runtime/overflow checks, and findings remain unchanged. Axe uses
this schedule after the screenshot:

- Light at 1280 px: one full scan per screen/state with the original tags
  `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, and `best-practice`.
- Dark at 1280 px: `withRules(["color-contrast", "link-in-text-block"])`.
  The latter checks whether inline links are distinguishable from surrounding
  text, including link-to-text contrast; see
  [Deque's rule explanation](https://dequeuniversity.com/rules/axe/4.13/link-in-text-block).
  These are all colour rules in the installed axe version's full tag set,
  verified by a unit test. Other structural rules are covered in light.
- At 390 px: skip axe except for these four structurally different states.
  Each exception receives a full scan in both themes:

  | State | Mobile structure covered |
  | --- | --- |
  | `profile` | Shared shell's mobile sidebar trigger replacing desktop navigation, once per theme |
  | `playground-inbox` | Mobile list replacing desktop resizable list/thread panes |
  | `playground-ivr-editor` | FlowPanel switching from an aside to a mobile sheet |
  | `playground-voice-bot-detail` | Mobile Settings entry point replacing the desktop settings rail |

The mobile exceptions and reasons live in `A11Y_MOBILE_STATES` in
`tests/e2e/a11y-policy.ts`. Closed menus/sheets are still unvisited; no new
interaction states were added. Responsive styling with the same controls
uses the desktop structural scan.

The tour timeout remains **20 minutes**, targeting roughly 15 minutes on the
QA host. Every scan has a hard **20-second budget**. An overrun records an
`a11y-scan-error` with kind `A11yScanTimeoutError`, persists findings immediately,
and aborts the tour. Closing its isolated context stops the pending scan before
another can start. This also prevents continuing with axe still running.

Console logs now show each scan's screen, theme, width, mode, start-frame counts,
elapsed seconds, and outcome. Errors print their kind and message immediately.
The final log reports total axe seconds, full/theme counts, the actual error
count, and counts grouped by error kind (including an explicit zero/empty map).
Engine errors remain fatal to the final gate, independent of the rule allowlist,
and their findings are persisted before further scene checks.

## Customer HTML preview frames

The two iframe creation paths (`EmailPreviewFrame` and raw HTML editor blocks)
use an empty sandbox and contain customer email/template HTML. Both now mark
those frames with `data-slot="email-preview-frame"`. All scan modes apply:

`AxeBuilder.exclude('iframe[data-slot="email-preview-frame"]')`

This is narrower than disabling all iframe scanning: it removes only those
preview frames and their customer contents from axe's frame traversal. The
surrounding application UI and any other frames remain eligible. The preview's
sandbox and visuals are unchanged. The exclusion is a content-scope boundary,
not a rule allowlist entry.

The installed AxeBuilder enumerates child frame contexts and injects axe into
them; axe's frame-response timeout defaults to 60 seconds. Its frame enumeration
does not receive builder run options, so `iframes: false` alone would still
allow adapter traversal. A DOM regression test exercises the installed
`axe.utils.getFrameContexts`: two marked sandboxed previews plus a UI frame
produce three frame contexts without the exclusion and only the UI frame with it.
Budget tests cover success, engine errors, and a scan that never resolves.

The earlier `1132.1s (11 full scans, 0 theme scans; includes scan errors)`
summary counted attempts rather than errors. The new Linux run confirms zero
scan errors and the restored performance budget. Per-scan/error logging and
the hard budget remain enabled to catch regressions.

Each violating node produces an `a11y` finding in
`$OPENSEND_TEST_RESULTS/tour/findings.json`, with the scene name, theme, width,
screenshot filename, and `detail` containing:

- `ruleId` and `impact` from axe;
- `target`, a selector including frame/shadow ancestry, capped at 240 characters;
- `summary`, axe's failure explanation, without copying the node's HTML;
- `allowlisted`, whether the rule is explicitly exempted from failure gating.

Every impact is recorded. Non-allowlisted `serious` and `critical` violations
fail the tour's final assertion. `minor`, `moderate`, and unknown impacts remain
diagnostic findings. An axe execution error is recorded as `a11y-scan-error` and
fails the tour; readiness failures in scheduled scan states still receive an
attempted scan. Findings
continue to be saved after each scene. Existing overflow, runtime, error-page,
and screen failures still fail; raw-code findings still only report.

### Raw-code history and false positives

`a11a42a` introduced the detector before this accessibility branch. Immediately
before axe was added (`174813d^`), the tour explicitly filtered `raw-code` out
of failures. This branch retains that non-failing behavior; the 71 records are
pre-existing diagnostic checks, not a new axe failure condition.

The detector now excludes common attachment extensions (including
`document.pdf`, `image.png`, and filenames containing underscores). Existing
URL/domain/email/@handle exclusions remain, with a small extension for an
@handle whose prefix is in a separate text node. Variable paths such as
`contact.first_name`, `trigger.message.text`, and machine labels still report.
The unprefixed `opensend_ig_e2e` is indistinguishable from a machine label using
text alone and remains diagnostic for manual triage; no blanket exception for
snake-case names was added. Technical template names, variable examples and
headers may also be deliberate rather than defects.
