## R1 tool admission benchmark

`pnpm test:auth --maxWorkers=2 convex/toolAdmission.test.ts` measures the real internal admission mutations with `ctx.meta.getTransactionMetrics()` in convex-test 0.0.58, with transaction limits enabled. The fixture has 1,500 final transcript rows (500–1,999 characters each), 300 media rows and 32 tool rows. Seeding is outside the measured transaction; five distinct tool requests run per lane. Bytes are convex-test's document-size accounting, not deployed transaction telemetry. Wall time includes the local test runtime; the median reduces initial module-loading noise and is not a production latency claim.

| Admission                    | Before documents / bytes read | After documents / bytes read | Before / after wall time (median of five) |
| ---------------------------- | ----------------------------: | ---------------------------: | ----------------------------------------: |
| Built-in `gateway.tool`      |             1,833 / 2,332,906 |                    3 / 2,166 |                           23.26 / 3.10 ms |
| Toolkit `toolkitState.begin` |             1,833 / 2,332,906 |                    3 / 2,166 |                           22.28 / 2.48 ms |

Before the fix, the first built-in request took 1,583.25 ms including cold module loading; the first toolkit request took 28.88 ms. Both hydrated all 1,832 history rows for two admission counts. After the fix, the first built-in request took 1,427.28 ms including cold module loading; the first toolkit request took 7.46 ms. Steady admissions reduce measured documents by 99.84% and bytes by 99.91%. Timing remains local evidence; deployed timing still needs verification by the lead.

Commit `6e0e35e` adds the baseline benchmark; `5b7d59c` adds optional `admissionTranscriptCount` and `admissionToolCount` fields on calls. Counters saturate at 2,001 rows and 128 tools and update in the same mutation as every production transcript, media, note or tool insert. They count the entire call, across bot sessions. Admission still permits exactly 2,000 pre-existing rows and rejects at 2,001, rejects at 128 tool rows, and checks replay results before limits. A note tool admitted at 2,000 rows may still append both its note and tool log. No REST/SDK/MCP shapes changed.

Legacy calls without both fields initialize once using the existing `by_callId` index and `.take(2001)`. On the same long-call fixture, initialization reads 1,836 documents / 2,335,010 bytes and takes 24.81 ms for built-in admission or 22.89 ms for toolkit admission. The next request reads 3 documents / 2,166 bytes (2.62 / 2.50 ms). Initialization still hydrates the bounded history and retains its byte cost for large legacy rows; this change removes repeated hydration, not that one-time cost. No index backfill or schema migration is required.

The 29 admission tests cover both lanes and both counter states at 1,999/2,000/2,001 rows and 127/128 tools, duplicate requests, changed arguments, event deduplication, media completion, notes, validation versus execution failures, partial legacy counters, saturated counts and transactional rollback.

## Review coverage and boundaries

Checked gateway HTTP HMAC/auth and nonce handling, directory authentication, per-call operations, Janus/ESL teardown, audio queue bounds, IVR decisions/webhook deadlines, voice tool authority/deduplication, provider/session cleanup, transcript timestamps and billing reservations. Calling REST routes live in `convex/api/calling.ts`, voice REST in `convex/api/voice.ts`, IVR REST in `convex/ivr/routes.ts`; the requested `convex/whatsapp/calling/` directory does not exist here. Reviewed Janus, FreeSWITCH, drachtio and coturn configs statically; no high-confidence config defect was established.

The gateway HTTP server already serializes state-changing operations per call (`services/call-gateway/src/server.ts:315`). A direct-controller concurrency experiment therefore did not establish a production HTTP bug; that speculative change was removed. Production `.collect()` calls were not found in the requested calling/voice/IVR directories. Bounded caller-context hydration and transcript pagination were reviewed; R1 repeated admission hydration is fixed in the follow-up described above.

No edits were made to `components/`, `app/`, `scripts/`, `compose.yaml`, `.github/`, package scripts, or the private website. The original review needed no schema change; the R1 follow-up adds two optional call fields. REST/SDK response fields and types remain compatible; `webhook_signing_secret` remains a string with documented redaction semantics. Creation/rotation responses are recoverable only through the same write-scoped idempotent request, never a read-scoped reveal endpoint. Deploy Convex, gateway and voice-agent changes together before live verification.
